Bug hunt in `$ARGUMENTS` only. One file per invocation.

Check: rule ordering, insert vs append, address validation, IPv4/IPv6,
app-vs-OS state drift, original values captured before mutation, restore after
partial failure, double stop/restore, duplicate rules, leaked handles/threads/
sniffers, subprocess argument lists and exit codes, bare excepts, swallowed
errors, silent no-ops, stale state, races, cross-thread UI, false success
messages, Windows paths that pretend to work.

Per finding: ID, severity, file:line, why it's wrong, evidence. Regression test
for each confirmed bug, then the fix. Or state why the file is clean.
Write to audit.md. Stop.

## Verify before every commit (mandatory)

A per-file check is not enough — newly added TEST files slip through it. Before
committing a batch:

1. Run Ruff and Mypy against BOTH the modified source file AND its associated
   test file(s), e.g. `ruff check <src> <test>` and `mypy <src> <test>`.
2. Then run the FULL project gates and read their actual output:
   - `pytest -v`
   - `ruff check .`
   - `ruff format --check .`
   - `mypy .`
3. Do NOT commit while any newly introduced error remains. Fix it first.
4. Distinguish pre-existing failures from regressions this batch caused:
   - The pre-existing uncommitted WIP is not `ruff format`-clean (~20+ files).
     That is expected; your own changed/added files must be format-clean.
   - A failure that only appears after your change is a regression you own.
   - State in the report which failures are pre-existing vs introduced.
5. Do not silence errors with broad `# type: ignore` / `except Exception` just to
   go green. Use a targeted, code-specific ignore (e.g.
   `# type: ignore[attr-defined]` for scapy's dynamic `scapy.all` symbols) only
   when the error is a known library/environment artifact, and say why.
